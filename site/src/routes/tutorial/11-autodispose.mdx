# autodispose

`three.js` objects hold onto GPU resources — geometries, materials,
textures, render targets. To free them you have to call `.dispose()`
explicitly. Forget, and they leak.

`solid-three` does it for you. Every three.js object created by a
`<T.*>`, `<Entity>`, or `<Resource>` is wrapped in an `onCleanup` that
calls `.dispose()` when the component unmounts.

Click "remove". The cube vanishes from the scene; behind the scenes its
`BoxGeometry` and `MeshNormalMaterial` are both disposed. Click "add" and
fresh ones are created. You can do this all day without leaking.

## When you create objects yourself

Occasionally you construct a three.js object outside the declarative
tree — a render target for a custom pass, a `BufferGeometry` you mutate
manually, a one-off `Color`. To opt into the same lifecycle, wrap it with
`autodispose(...)` inside a component:

```tsx
import { autodispose } from "solid-three"

function MyComponent() {
  const target = autodispose(new THREE.WebGLRenderTarget(512, 512))
  // ...use target...
}
```

`autodispose` registers an `onCleanup` that calls `target.dispose()` when
the component unmounts. Same lifecycle as everything else — you stay out
of GPU memory bookkeeping.
