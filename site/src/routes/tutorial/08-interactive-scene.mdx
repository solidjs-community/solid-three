# A small game

You've now seen every piece. Time to put them together into something that
actually plays.

<Demo code={interactiveScene} />

A 3x3 grid of cubes. One lights up at a time. Click the lit one before time
runs out — every hit scores a point and lights up a new cube. You have 20
seconds.

That's a real game, written in about 150 lines of `solid-three`. And
the only thing about it that's specifically 3D is the choice to use
`<T.Mesh>` instead of `<button>`.

## What's actually in here

Reading top-to-bottom:

- **Game state** lives in four `createSignal`s — `running`, `score`,
  `activeIndex`, `timeLeft`. They're the same primitives you'd use for any
  Solid app.
- **The grid** is built once outside the component as a list of positions.
  We render the cubes with `<For>` — Solid's keyed list primitive, working
  exactly the way it does in any DOM tree.
- **Each `<Cube>`** is a custom component wrapping `<T.Mesh>` — same
  composition you'd use for any Solid component; props pass through. It
  uses `useFrame` to bob the active cube forward, and `onClick` with
  `event.stopPropagation()` to score.
- **A texture** is fetched once via `useLoader` and shared by all nine
  cubes. The active cube tints + glows tomato on top of it. Loading is
  gated by `<Suspense>` so nothing flashes before the texture lands.
- **The countdown** is a regular `setInterval` driving the `timeLeft`
  signal. The DOM panel reads it the same way the scene's `active` prop
  reads its signal — both are just Solid views over the same source of
  truth.
- **`<Show>`** swaps the "start" / "play again" button in and out — the
  same control-flow component you'd use for a modal or a toggle
  anywhere else.

## What you just shipped

A small whack-a-cube. Pointer events, signals, frame loop, custom
components, control flow — every chapter feeding into a single hundred-line
component that's complete enough to play. From here, you can keep building.
More cubes, a high-score table, a sound effect, a second player.

The shape of every other `solid-three` app you'll write is the same as
this one: signals describing state, JSX describing the scene, the smart-prop
pipeline keeping them in sync. The [API reference](/api) is there when you
need a specific export.

If you'd like a peek at where the library is heading next, the encore is
WebGPU.
