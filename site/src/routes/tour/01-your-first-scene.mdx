# Your first scene

Setting up a `three.js` scene normally means assembling a renderer,
a camera, and a `Scene` yourself, then driving an animation loop. The
`<Canvas>` component does all of that for you and gives you back a
JSX tree to fill.

```tsx
import { Canvas } from "solid-three"

export default () => <Canvas />
```

Empty for now. Everything else — cubes, lights, cameras — lives as
children of it.

To put a `three.js` class into that tree, you need a JSX component
that wraps it. `createT` is `solid-three`'s helper for doing that in
bulk: hand it an object of classes and you get back a proxy where
every key is its own JSX component.

For a single class — or one only known at runtime — you can skip the
namespace and wrap it inline with
[`<Entity from={Class}>`](/reference/components/entity) instead.

<Demo code={createTSnippet} url={createTUrl} />

The colour comes from `MeshNormalMaterial`, which tints each face by its
surface normal — a handy debugging material because it makes geometry
visible without any lights.

`T.Mesh`, `T.BoxGeometry`, `T.MeshNormalMaterial` — every class in the
`THREE` namespace becomes available the same way. We'll pass the full
namespace throughout this tutorial because it's easier to follow when
imports aren't the point. (In real apps you'd hand `createT` a curated
object to keep your bundle small; see
[the API reference](/reference/components/t) for the details.)

Three new ideas appeared in that snippet — `createT`, the `T.*`
namespace, and the way `<T.Mesh>` consumes its children as a geometry
and a material.
We unpack the last one in the next chapter, where nesting becomes the
scene graph.
