# useProps

`useProps` is the smart-prop pipeline that powers every `<T.*>` and `<Entity/>` component. It applies a record of props to a `three.js` object reactively — coercing values into the shapes three expects, walking dashed paths into nested setters, wiring up event listeners, attaching children, and disposing on cleanup.

Call it directly when you wrap your own `three.js` object (custom controls, third-party libraries, ad-hoc instances).

**Parameters:**

- **accessor**: Either the target `three.js` object, an accessor that returns it, or `undefined`. The hook waits for a non-`undefined` value before applying anything.
- **props**: Object containing props to apply (including `ref`, `args`, `attach`, `children`, and any `three.js` properties).
- **context** *(optional)*: The `Context` slice (`requestRender`, `gl`, `props`) the pipeline reads from. Defaults to `useThree()`. Useful when calling `useProps` outside a `<Canvas>` provider — e.g. tests, or a custom renderer host.

<details>
<summary>Typescript Signature</summary>

```tsx
function useProps<T extends Record<string, any>>(
  accessor: T | undefined | Accessor<T | undefined>,
  props: any,
  context?: Pick<Context, "requestRender" | "gl" | "props">,
): void
```

</details>

**Usage:**

```tsx
const mesh = new Mesh(new BoxGeometry(), new MeshBasicMaterial())

// Apply solid-three props reactively to the mesh
useProps(mesh, props)
```

A typical wrapper looks like this — instantiate (often via `createMemo` so the object rebuilds when `args` change), hand the accessor to `useProps`, and return `null`:

```tsx
export function OrbitControls(props: S3.Props<typeof ThreeOrbitControls>) {
  const three = useThree()
  const controls = createMemo<ThreeOrbitControls>(() => {
    const next = autodispose(new ThreeOrbitControls(three.camera))
    next.connect(three.gl.domElement)
    return next
  })

  useFrame(() => controls().update())

  useProps(controls, props)

  return null
}
```

## What runs when a prop changes

Each prop is wrapped in its own `createRenderEffect`. When a signal a prop reads updates:

- only that prop's effect re-runs — sibling props are untouched;
- the effect calls the coercion pipeline below, which mutates the existing `three.js` object in place;
- `needsUpdate` is flagged on materials/geometries as needed;
- if the renderer is on `frameloop="demand"`, a render is requested.

The wrapper function itself (the component body) runs **once** at mount. Reactive prop content does not re-mount the component — Solid's per-effect tracking means the rebuild surface is one property at a time. The exception is `args`: changing `args` rebuilds the entity (see below).

## Coercion rules

Applied top-to-bottom by `applyProp`. The first rule that matches wins; later rules only run if earlier rules fell through. `source` is the target object, `key` is the prop name, `value` is the new value.

| #  | Condition                                                                                       | Action                                                                                                       |
| -- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 1  | `value === undefined`                                                                            | skip (never overwrites with `undefined`)                                                                     |
| 2  | `key` contains `-`                                                                               | split on `-`, recurse into the nested object (see [Dashed paths](#dashed-paths))                              |
| 3  | `key` is in the `NEEDS_UPDATE` list (see below) and its truthiness flips                          | set `source.needsUpdate = true` **before** the assignment continues                                          |
| 4  | `source` has `colorSpace`/`outputColorSpace` and `key` is `encoding` / `outputEncoding`           | alias to `colorSpace` / `outputColorSpace`, mapping `sRGBEncoding → "srgb"`, anything else → `"srgb-linear"` |
| 5  | `key` is an event name (`onClick`, `onPointerMove`, …)                                            | register on the event system (`Object3D` instances only — warns otherwise) and **return**                    |
| 6  | `source[key].copy` exists, `value.constructor === source[key].constructor`, and `source[key]` is not a writable own property | `source[key].copy(value)`                                                          |
| 7  | `source[key].set` exists and `value` is an array                                                 | `source[key].fromArray(value)` if available, else `source[key].set(...value)`                                |
| 8  | `source[key].set` exists, `value` is not an object, `source[key]` is **not** a `Color`, and `source[key].setScalar` exists, and `value` is a number | `source[key].setScalar(value)`                          |
| 9  | `source[key].set` exists and `value` is not an object                                            | `source[key].set(value)` — this is where `color="red"`, `color={0xff8800}`, etc. land via `Color.set`        |
| 10 | otherwise                                                                                        | `source[key] = value` (overwrite); if the assigned value is a `Texture` with `RGBAFormat`/`UnsignedByteType`, auto-reconcile its `colorSpace` against the renderer's `outputColorSpace` (subscribing to canvas-level `linear`/`flat`) |

Then, in a `finally` after every prop (rules 5–10):

- if `"needsUpdate" in source`, set `source.needsUpdate = true` — every assigned prop bumps `needsUpdate` on materials/geometries that have it, not only the `NEEDS_UPDATE` list;
- if `frameloop === "demand"`, `context.requestRender()` is called.

### What this means in practice

```tsx
<T.Mesh
  // Array → Vector3.set(1, 0, 0)
  position={[1, 0, 0]}
  // Number with setScalar → scale.setScalar(2) (uniform scale on all axes)
  scale={2}
  // Tuple via Euler.set(...) — Euler has .set, accepts (x, y, z, order?)
  rotation={[Math.PI / 4, 0, 0]}
>
  <T.MeshStandardMaterial
    // CSS string → Color.set("cornflowerblue")
    color="cornflowerblue"
    // Tuple → Color.set is exhausted, falls to fromArray-equivalent
    emissive={[1, 0.4, 0.2]}
    // Hex → Color.set(0xff8800)
    specular={0xff8800}
  />
</T.Mesh>
```

### `NEEDS_UPDATE` truthiness list

These material props additionally flip `needsUpdate = true` *before* the new value is assigned, when their truthiness changes — so swapping a `map` on or off doesn't silently keep the compiled shader:

`map`, `envMap`, `bumpMap`, `normalMap`, `transparent`, `morphTargets`, `skinning`, `alphaTest`, `useVertexColors`, `flatShading`.

This is on top of the unconditional `needsUpdate = true` that runs in the `finally` after every prop application.

### Encoding aliasing (since three r152)

`encoding` and `outputEncoding` are legacy aliases. When the target has a `colorSpace` / `outputColorSpace` field, the pipeline rewrites them in place:

- `encoding` → `colorSpace`
- `outputEncoding` → `outputColorSpace`
- the legacy `sRGBEncoding` numeric value maps to `"srgb"`; anything else maps to `"srgb-linear"`.

### Texture sRGB auto-reconciliation

When a `Texture` value lands via the overwrite branch (rule 10) **and** the texture is `RGBAFormat` / `UnsignedByteType` (the formats three requires for sRGB textures since r137), its `colorSpace` is auto-set to the renderer's `outputColorSpace`. This effect subscribes to the canvas-level `linear` and `flat` props, so flipping either updates assigned textures automatically.

## Dashed paths

Hyphenated keys reach into nested objects and apply the same coercion rules at the leaf:

```tsx
<T.DirectionalLight
  castShadow
  shadow-mapSize-width={1024}
  shadow-mapSize-height={1024}
  shadow-bias={-0.0001}
/>
```

Reads as: `light.shadow.mapSize.width = 1024`, `light.shadow.mapSize.height = 1024`, `light.shadow.bias = -0.0001`. Each leaf goes through the coercion table above — so `position-x={1}` lands on a number, while `material-color="blue"` goes through `Color.set`.

If both a parent prop and a child sub-prop are present (e.g. `position={[0, 0, 0]}` and `position-x={2}`), the sub-prop is applied immediately after the parent — child wins.

## `args` — constructor parameters

`args` is spread into the entity's constructor: `new BoxGeometry(...args)`. It is not a runtime property — it determines how the object is *built*. Changing `args` therefore **rebuilds the entity** (the old one is disposed, the new one is mounted in its place). This is what you want for things that don't have setters for their constructor parameters (geometry sizes, light shadow map dimensions before instantiation, etc.).

```tsx
const [size, setSize] = createSignal(1)

<T.Mesh>
  {/* Resizing rebuilds the BoxGeometry */}
  <T.BoxGeometry args={[size(), size(), size()]} />
  <T.MeshStandardMaterial color="cornflowerblue" />
</T.Mesh>
```

For everything that *does* have a runtime setter, use a regular prop — it mutates in place instead of rebuilding.

## `attach` — slot assignment

By default `solid-three` figures out where a child belongs:

- `Material` instances → `parent.material`
- `BufferGeometry` instances → `parent.geometry`
- `Fog` instances → `parent.scene.fog`
- `Object3D` instances → added to `parent.children`

Override with an explicit `attach` prop when the default isn't what you want — for example, attaching a texture into `material.map`, or assigning a second material to a `material-1` slot:

```tsx
<T.MeshStandardMaterial>
  <Resource loader={TextureLoader} url="diffuse.jpg" attach="map" />
  <Resource loader={TextureLoader} url="normal.jpg" attach="normalMap" />
</T.MeshStandardMaterial>
```

`attach` accepts:

- a **string** — dashed paths work the same way they do for props (`attach="material-emissiveMap"` lands at `parent.material.emissiveMap`);
- a **function** — `(parent, child) => cleanup`. Useful for non-property attachments (e.g. `addEventListener` style hooks). The returned cleanup runs on unmount.

## `ref`

Both function refs and object refs are supported:

```tsx
let mesh: Mesh | undefined
<T.Mesh ref={mesh}>
  …
</T.Mesh>

// or
<T.Mesh ref={instance => doSomethingWith(instance)} />
```

Function refs fire inside a `createRenderEffect`, so they re-run if the underlying object identity changes (e.g. after an `args` rebuild).

## `onUpdate`

A special prop, not a `three.js` field. Fires after every prop application pass for the entity, with the entity itself as the argument. Useful as a "props are settled" hook for derived setup that can't be expressed as a single prop.
