# The T proxy

Writing `<Entity from={THREE.Mesh}>` for every class gets old fast.
`solid-three` ships a helper called `createT` that takes a namespace of
`three.js` classes and returns a proxy where every key is its own
`<Entity>`-shaped component:

<Demo code={`
import * as THREE from "three"
import { Canvas, createT } from "solid-three"

const T = createT(THREE)

export default () => (
  <Canvas camera={{ position: [0, 0, 3] }}>
    <T.Mesh>
      <T.BoxGeometry />
      <T.MeshNormalMaterial />
    </T.Mesh>
  </Canvas>
)
`} />

Same cube. `T.Mesh` is exactly `<Entity from={THREE.Mesh}>` — `solid-three`
looks up `Mesh` on the namespace you handed to `createT` and constructs it for
you.

## What gets bundled

The convenience has a cost. `createT(THREE)` references the entire `THREE`
namespace, so your bundler ships every `three.js` class — geometries,
materials, loaders, post-processing, the lot — whether you use them or not.
With `Entity`, imports are explicit and the bundler only keeps what you reach
for.

There's a middle path: hand `createT` a hand-picked object instead of the whole
namespace.

<Demo code={`
import { Mesh, BoxGeometry, MeshNormalMaterial } from "three"
import { Canvas, createT } from "solid-three"

const T = createT({ Mesh, BoxGeometry, MeshNormalMaterial })

export default () => (
  <Canvas camera={{ position: [0, 0, 3] }}>
    <T.Mesh>
      <T.BoxGeometry />
      <T.MeshNormalMaterial />
    </T.Mesh>
  </Canvas>
)
`} />

Now `T.*` is just as terse, but only the three classes you imported end up in
the bundle. For the rest of this tutorial we'll pass the full `THREE`
namespace — easier to follow when the imports aren't the point. In real apps,
the curated object is usually what you want.
