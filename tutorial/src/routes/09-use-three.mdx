# useThree

`useFrame`'s callback already gets the scene `context` as its first
argument. `useThree` is the same thing, available *outside* of a frame
callback — when you need to set up the camera, read the canvas size, or
hand a renderer reference to a side effect.

The context exposes:

- `gl` — the `THREE.WebGLRenderer`
- `scene` — the root `THREE.Scene`
- `camera` — the active camera
- `clock` — the renderer's `THREE.Clock` (gives `elapsedTime` and `delta`)
- `canvas` — the underlying `<canvas>` element
- `bounds`, `viewport`, `dpr` — pixel-space and CSS-space dimensions
- `raycaster` — the active raycaster
- `requestRender` — manually trigger a frame in `frameloop="demand"`

Two child components share the same context: `OrbitingCamera` writes to
`camera.position` each frame, and `Reporter` reads it back into an HTML
overlay outside the canvas. Both call `useThree()` to get there.

## When to reach for it

In practice, you'll use `useThree` whenever you need scene state somewhere
other than per-frame. Common reasons:

- a setup effect that needs to know the canvas size or DPR
- handing the renderer (`gl`) to a screenshot helper, an effect composer,
  or an external library
- a derived signal that depends on camera or scene state

For per-frame work, the `context` argument to `useFrame` already covers
you — there's no need to call `useThree` separately.
