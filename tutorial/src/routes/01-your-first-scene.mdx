# Your first scene

A `three.js` scene needs three things:

- a **renderer** to draw pixels,
- a **camera** to decide what gets drawn,
- and a **scene** to hold everything else.

In `solid-three` you get all three by mounting one component:

```tsx
import { Canvas } from "solid-three"

export default () => <Canvas />
```

That `<Canvas>` is the whole boilerplate. Everything else — the cubes, the
lights, the cameras you might want later — lives as children of it.

`solid-three` gives you two ways to put `three.js` classes into that tree:

- [the explicit way, with `<Entity>`](#the-explicit-way-entity)
- [the sugary way, with `createT`](#the-sugary-way-createt)

They produce the same scene; they only differ in ergonomics.

## The explicit way: `<Entity>`

`<Entity from={...}>` is the most direct primitive: hand it a `three.js`
class, and it instantiates one in the scene.

<Demo code={`
import * as THREE from "three"
import { Canvas, Entity } from "solid-three"

export default () => (
  <Canvas camera={{ position: [0, 0, 3] }}>
    <Entity from={THREE.Mesh}>
      <Entity from={THREE.BoxGeometry} />
      <Entity from={THREE.MeshNormalMaterial} />
    </Entity>
  </Canvas>
)
`} />

A square — the front face of a cube, viewed head-on. The colour comes from
`MeshNormalMaterial`, which tints each face by its surface normal: a handy
debugging material because it makes geometry visible without any lights.

Because each class is imported by name, the bundler only ships the ones you
reach for.

## The sugary way: `createT`

Writing `<Entity from={THREE.Mesh}>` for every class gets old fast. `createT`
takes a namespace of `three.js` classes and hands you back a proxy where every
key is its own `<Entity>`-shaped component.

<Demo code={`
import * as THREE from "three"
import { Canvas, createT } from "solid-three"

const T = createT(THREE)

export default () => (
  <Canvas camera={{ position: [0, 0, 3] }}>
    <T.Mesh>
      <T.BoxGeometry />
      <T.MeshNormalMaterial />
    </T.Mesh>
  </Canvas>
)
`} />

Same cube. `T.Mesh` is exactly `<Entity from={THREE.Mesh}>` — `createT` just
saves the typing.

The tradeoff: `createT(THREE)` references the whole namespace, so the bundler
ships every `three.js` class regardless of what you use. You can keep the
sugar and stay tree-shakeable by handing `createT` a curated object instead:

<Demo code={`
import { Mesh, BoxGeometry, MeshNormalMaterial } from "three"
import { Canvas, createT } from "solid-three"

const T = createT({ Mesh, BoxGeometry, MeshNormalMaterial })

export default () => (
  <Canvas camera={{ position: [0, 0, 3] }}>
    <T.Mesh>
      <T.BoxGeometry />
      <T.MeshNormalMaterial />
    </T.Mesh>
  </Canvas>
)
`} />

`T.*` stays terse, but only the classes you imported survive into the bundle.
For the rest of this tutorial we'll pass the full `THREE` namespace — easier
to follow when the imports aren't the point. In real apps, the curated object
is usually what you want.
